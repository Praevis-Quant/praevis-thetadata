# praevis-thetadata 0.1.6

**A patch release of `0.1.5`: the fixes from the 0.1.5 review, a hardened
release pipeline, and one exit-code correction in the CLI.**
praevis-thetadata is an independent, unofficial client for ThetaData's
market-data service. It is not affiliated with, sponsored by or endorsed by
Theta Data Inc.

## Behaviour change

- **CLI: an invalid `--profile`, `--auth-url`, `--insecure` combination or
  `--timeout` now exits 2**, the documented code for argument errors. It
  exited 1. The README and the CLI's requirements always stated 2; scripts
  that tested for 1 on these errors need updating.

## Fixed

- **Jobs:** a job's timeout now also covers the one strike-list request an
  all-strike fine `option_history_quote` plan makes before splitting.
- **Real-time stream (experimental):** `close()` and drop no longer hang
  when the event queue is full as the socket ends.
- **Parquet sink:** each sink writes its own new partial file
  (`<name>.<pid>-<n>.partial`), never follows a symlink, and without
  `overwrite` never replaces a file that appeared while it wrote
  (`SinkError::Exists`). With `overwrite`, the move is one atomic rename.
  Python's `to_parquet` behaves the same.
- **Python:** a timeout too large for a duration raises `ValueError`
  instead of `PanicException`.
- **SBOMs:** each lists exactly the crates its artifact is built from. The
  0.1.5 SBOMs also listed crates those artifacts do not contain (`openssl`,
  and `keyring` and D-Bus outside the CLI).

## Added

- **`AuthConfig::validate()`** (auth): the configuration checks
  `AuthClient::new` makes, without I/O or a runtime.

## Release and assurance

- **The organisation's release standard:** an annotated tag, a dated
  CHANGELOG entry and committed release notes are required. Signing
  happens only on the tag push. This release was drafted, checked and
  only then published, and every published file is verified from the
  outside on each platform's native runner (the `verify` job).
- **Two more fuzz targets** (the legacy table decoder and the gRPC framing
  guard), and a repository check that allows exactly the two audited
  `unsafe` sites in shipped source.
- **Dependencies:** `url` 2.5.9 (RUSTSEC-2026-0592; `0.1.5` does not call
  the affected function), and `prost` 0.14.6 and `zstd` 0.14.4.

**API:** additive (`AuthConfig::validate()`). The full list, including
unpublished tooling, is in
[CHANGELOG.md](https://github.com/Praevis-Quant/praevis-thetadata/blob/v0.1.6/CHANGELOG.md).

## Install

```toml
praevis-thetadata-client = "0.1"       # resolves 0.1.6
praevis-thetadata-stream = "=0.1.6"    # optional, real time, experimental: pin it
```

```text
pip install --upgrade praevis-thetadata
cargo install praevis-thetadata-cli --locked    # or download an executable below
```

**Verify a download:**

```text
sha256sum --check --ignore-missing SHA256SUMS
gh attestation verify <file> --repo Praevis-Quant/praevis-thetadata \
  --signer-workflow Praevis-Quant/praevis-thetadata/.github/workflows/build-release.yml \
  --source-ref refs/tags/v0.1.6
```

The same command verifies a crate downloaded from crates.io
(`https://static.crates.io/crates/<crate>/<crate>-0.1.6.crate`).

Offline: add `--bundle praevis-thetadata-0.1.6.intoto.jsonl
--custom-trusted-root trusted_root.jsonl` ([how](https://github.com/Praevis-Quant/praevis-thetadata/blob/v0.1.6/docs/releasing.md#verifying-a-release)).

The wheels need CPython 3.10 or newer. The known gaps of `0.1.0` still
apply ([list](https://github.com/Praevis-Quant/praevis-thetadata/blob/v0.1.6/docs/releases.md#known-gaps-shipped-in-010)),
less the one fixed in `0.1.1`. Coverage per endpoint, including which
wrappers are not live-verified, is in the
[coverage table](https://github.com/Praevis-Quant/praevis-thetadata/blob/v0.1.6/docs/endpoints/coverage.md). The security assurance report covers this
release ([report](https://github.com/Praevis-Quant/praevis-thetadata/blob/v0.1.6/docs/security/assurance-report.md)).
